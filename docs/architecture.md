# Архитектура и описание решения

## Назначение
Сервис принимает ссылку на изображение, определяет основные предметы (use-case 1), затем по подтвержденным пользователем названиям определяет материалы предметов (use-case 2). Все вызовы AI логируются в `ai_calls` для аудита, а результаты нормализуются и сохраняются в БД.

## Потоки обработки
### 1) Основные предметы (`POST /api/recognition`)
1. Создается `recognition_requests` со статусом `CREATED`.
2. Скачивается изображение, вычисляется `image_hash` (SHA-256), сохраняется в локальное хранилище (`image_storage_key`).
3. Отправляется промпт `main.v1` и изображение в AI.
4. Ответ парсится, создаются `predicted_objects`.
5. Статус запроса меняется на `MAIN_DETECTED`. При ошибках — `FAILED`.

### 2) Материалы (`POST /api/recognition/{id}/materials`)
1. Проверяется, что запрос существует и статус допускает обработку (`MAIN_DETECTED` / `CONFIRMED` / `FAILED`).
2. Скачивается изображение по `image_url` (используется исходная ссылка).
3. Отправляется промпт `materials.v1` с массивом подтвержденных предметов.
4. Ответ парсится и сохраняется: `confirmed_objects` (нормализация пользовательских названий), `materials` (upsert по имени), `confirmed_object_materials` (M:N связи).
5. Статус запроса меняется на `MATERIALS_DETECTED`.

## Модель данных
Энумы:
- `ai_stage`: `MAIN_OBJECTS`, `MATERIALS`.
- `request_status`: `CREATED`, `MAIN_DETECTED`, `CONFIRMED`, `MATERIALS_DETECTED`, `FAILED`.

Базовая схема указана в `docs/db-schema.mmd`.

## Интеграция с AI
Провайдер: GigaChat (настраивается через `ItemRecognition.Api/appsettings*.json` или User Secrets).
В `ai_calls` сохраняется:
- версия промпта,
- полный текст промпта,
- payload запроса,
- raw JSON ответа,
- длительность,
- признак успеха и текст ошибки.

## Промпты (в явном виде)
### main.v1
```text
Ты — система компьютерного зрения для инвентаризации предметов.
Определи основные предметы на изображении. Основной предмет — главный объект съемки, который пользователь хочет идентифицировать как отдельную позицию.
Верни строго JSON без пояснений и без markdown.
Схема ответа:
{
  "objects": [
    { "name": "string", "isPrimary": true, "confidence": 0.0, "rank": 1 }
  ]
}
Правила:
- Верни от 1 до 5 объектов.
- isPrimary: true для основных предметов. Если сомневаешься, можешь добавить 1-2 второстепенных кандидата с isPrimary: false. Минимум один объект должен быть isPrimary: true.
- rank: уникальный порядок по убыванию важности/вероятности начиная с 1.
- name: короткое, конкретное русское название предмета в именительном падеже.
- Если уверенно виден тип/назначение/модель — уточняй; если нет уверенности, выбирай более общее название.
- Не включай людей, части тела, фон, элементы помещения, отражения, тени, текстовые подписи и случайные второстепенные объекты.
- Не добавляй материалы, бренды, размеры и оценки состояния в name.
- Не добавляй дубликаты и синонимы одного и того же предмета.
- Используй только то, что реально видно; не додумывай невидимые предметы.
- Никаких дополнительных ключей.
```

### materials.v1
```text
Ты — система компьютерного зрения. Определи материалы указанных предметов на изображении.
Верни строго JSON без пояснений и без markdown.
Схема ответа:
{
  "items": [
    { "name": "string", "materials": ["string"] }
  ]
}
Правила:
- items должен содержать ровно столько объектов, сколько передано предметов, в том же порядке.
- name должен точно совпадать с одним из переданных названий.
- Для каждого предмета верни набор основных материалов (обычно 1-4).
- Для составных предметов укажи материалы корпуса и функциональных частей.
- Используй базовые, обобщенные названия материалов (металл, пластик, дерево, стекло, бумага, ткань, кожа, резина, керамика, камень, композит, чернила и т.п.).
- Если не уверен в частном виде, выбирай более общее название (например, "металл" вместо "сталь").
- materials: массив без дубликатов, в порядке убывания уверенности.
- Если материал нельзя обоснованно определить или предмет не виден, верни пустой массив.
- Никаких дополнительных ключей.
Переданные предметы (JSON-массив): {items}
```

## Ограничения
- Допустимые типы изображений: `image/jpeg`, `image/png`, `image/webp`.
- Максимальный размер файла: 8 МБ (настраивается).
- Изображение скачивается по URL, затем хранится локально (ключ `image_storage_key`).

## Порядок запуска
Кратко:
1. `docker compose -f deploy/docker-compose.yml up -d`
2. Настроить User Secrets (строка подключения + ключ GigaChat).
3. `dotnet run --project ItemRecognition.Api`
Полные шаги и тестовые запросы — в `README.md`.
